Mobile UX · CSCI 443

Animated Bible App

A mobile prototype for watching animated Bible stories alongside the verses they come from.

Project credit · Finn Wells-Minthorn and collaborator Daniel Henry. Daniel Henry is credited on the source presentation. The process and artifacts below are presented at the project level.

Problem

Paywalls can make it difficult for curious or budget-conscious viewers to try animated Bible stories. The design challenge was to make a complete first story easy to access and keep its source verses in view.

Research and synthesis

The project documents text-based interviews with five Christians aged 19–29 from a personal network. All five wanted a free option. Their answers informed empathy maps and Barry, a college-aged visual learner who wants the story and scripture together. The findings reflect this interview group.

Design decisions

The project moved from low-fidelity sketches and a user flow to seven linked iPhone artboards in Adobe XD, using shared components for cards, buttons and navigation. The flow starts with a free viewing option without sign-up. Story details offer adult and kids versions and show an accuracy-review badge as a design concept. In the player, the active verse follows the video, with a toggle for independent reading.

Evaluation and status

The project report documents a walkthrough of the main path in Adobe XD Preview and a review against Nielsen’s ten usability heuristics. The offline banner shows system status, undo supports user control, and a press-and-hold exit helps prevent accidental departures from Kids mode. The report proposes participant usability testing as a next step.

Prototype gallery

Outcome

The Adobe XD prototype presents a three-tap path from Welcome to the first story, with the source verses visible during playback. A follow-up study could observe first-time viewers finding a story, switching versions and resuming an offline download.

Plugin development · C# / LabAPI

Nuke Events

A server plugin for SCP: Secret Laboratory that manages configurable round events and tells players what the lobby has selected.

UI collaboration · I worked with my best friend on the plugin’s interface design.

View the Nuke Events repository

Problem

A special round changes the rules players expect. The plugin needs to communicate the selected event before the round starts and let server operators control which events are available.

Tools and approach

The plugin is written in C# for .NET Framework 4.8 and uses LabAPI round hooks. The implementation splits configuration, selection and the player-facing display. It selects the result when the countdown starts and then presents that result through a rolling list of options.

  1. Configure Enable event modes and set the chance of a normal round.
  2. Select Choose from enabled events or the configured normal-round option.
  3. Announce Show the selection and resulting event name in lobby hints.

In-game UI

Implementation and verification

The plugin registers six event types, including Blackout, Speed Demon and Infection. It separates selection logic from hint presentation and clears plugin state on disable. The repository includes automated checks for hint replacement, display cleanup and preserving the preselected event during the lobby roll.

Usability and player testing

The lobby’s selection message and result illustrate visibility of system status. A player walkthrough could check whether players notice and understand the selected event before the countdown ends. The public repository documents automated checks, and player feedback remains an open question.
